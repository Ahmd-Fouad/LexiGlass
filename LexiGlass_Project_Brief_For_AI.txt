# LexiGlass Project Brief for Claude/Codex

You are working on LexiGlass, a full-stack English study companion app.

## 1. Product purpose

LexiGlass is a personal English learning app for vocabulary, phrases, grammar topics, spaced repetition, quizzes, and progress tracking.

The goal is to make it feel like a serious English learning product, not just a simple flashcard CRUD app.

The user is learning English around B1 to B2 level and wants the app to help with:

- saving useful words and phrases
- adding English definitions
- adding Arabic translations manually
- adding example sentences
- reviewing vocabulary with spaced repetition
- taking vocabulary and grammar quizzes
- tracking weak words and progress
- practicing real useful English phrases

## 4. Important auth/security behavior

Every user's data must remain isolated.

For every read, update, delete, review, quiz, or stats action, always verify ownership using the logged-in user ID.

Correct pattern:

```ts
where: {
  id: itemId,
  userId: currentUser.id
}
```

Avoid unsafe access like:

```ts
where: {
  id: itemId
}
```

JWT cookies must remain httpOnly. In production, cookies should use secure settings.

JWTs include a database-checked session version so logout-all can revoke old sessions. Unsafe browser API methods must pass centralized same-origin Origin/Referer checks. Auth, provider, dictionary, quiz, review, sync, and writing endpoints use database-backed rate limits.

Every online or offline review action has a durable client action ID. Database uniqueness guarantees one schedule transition. ReviewLog stores authoritative before/after SRS snapshots; undo restores only the latest server snapshot and never trusts client-supplied prior state.

## 6. Spaced repetition behavior

The app uses a simplified SM-2 system.

Ratings:

- Again
- Hard
- Good
- Easy

Rules:

- Again resets card to due now
- Hard gives small progress
- Good increases interval
- Easy increases interval more
- Intervals are capped at 7 days
- Wrong quiz answers map to Again
- Correct quiz answers map to Good

Important file:

```txt
lib/srs.ts
```

Do not break the 7-day interval cap unless explicitly requested.

## 7. Vocabulary quiz behavior

Vocabulary quiz should choose cards by priority:

1. due cards
2. previously wrong cards
3. difficult cards
4. older / longest-unreviewed cards

Question types include:

- meaning multiple choice
- reverse multiple choice
- fill-in-the-blank from example sentence
- true/false
- cloze-style questions if added

Important file:

```txt
lib/quiz.ts
```

Quiz questions are server-authoritative. Quiz start persists `QuizQuestion` rows and returns only safe public payloads. The correct answer is not sent before submission. Quiz answer accepts the issued question ID, session ID, stable submission ID, and user answer; it grades and updates QuizAnswer, SRS, ReviewLog, and mistakes atomically. Retry-wrong remains local practice and never changes the stored result.

## 9. Smart Definition and Example Assistant

This is an important feature inside the Flashcard Add/Edit form.

The purpose:

When the user types a word or phrase, the app helps suggest:

- English definition
- example sentence
- synonyms/antonyms as helper text if available
- phonetic/audio only as helper metadata, not as visible form fields for now

The assistant must be inside the Add/Edit Word form, not a separate dictionary page.

User flow:

1. User types a word or phrase.
2. User focuses the Meaning field or clicks Suggest definition.
3. Definition suggestions appear.
4. Nothing is applied automatically.
5. User clicks Use this definition.
6. User focuses the Example field or clicks Suggest example.
7. Example suggestions appear.
8. User clicks Use this example.
9. User can always write manually.

### FreeDictionaryAPI.com

Fallback dictionary source if dictionaryapi.dev has no useful result.

### Datamuse API

Not a dictionary.

Use only for:

- related words
- spelling suggestions
- similar words
- phrase suggestions

Datamuse results must be labeled as:

```txt
Related suggestions
```

Never show Datamuse suggestions as real definitions.

### Tatoeba

Used for example sentences.

For phrase inputs, Tatoeba examples must contain the exact full phrase.

## 11. Phrase handling rules

Phrase handling is critical.

For phrases like:

- winning formula
- get rid of
- look forward to

Never fallback to one random word and show unrelated examples.

Bad example:

```txt
Term: winning formula
Example: He deserved to win.
```

This is unacceptable because it only contains "win", not "winning formula".

Correct example:

```txt
After several failed attempts, we finally found a winning formula for improving our study routine.
```

For phrase inputs:

- definition lookup should check local phrase dictionary first
- examples must contain the full exact phrase
- if no exact example exists, show a clean empty state
- do not show weak examples by default

## 12. Current dictionary lookup priority

For phrases:

1. Local phrase dictionary exact match
2. dictionaryapi.dev exact lookup
3. FreeDictionaryAPI exact lookup
4. Datamuse related suggestions only

For single words:

1. dictionaryapi.dev
2. FreeDictionaryAPI
3. local fallback examples if available
4. Datamuse related suggestions only

## 13. Example quality rules

Examples should be useful for English learning.

Good examples:

```txt
I need to get rid of old files to free up space on my laptop.
The company restricts access to sensitive project files.
After several failed attempts, we finally found a winning formula for improving our study routine.
```

Bad examples:

```txt
Get rid of it.
There are no restrictions.
He deserved to win.
```

Example scoring should:

- prefer examples containing the exact target
- require exact full phrase for phrases
- prefer 8 to 22 words
- penalize very short examples
- penalize very long examples
- remove duplicates
- remove fragments
- keep best 3 to 5 examples

Important helper:

```ts
scoreExampleSentence(sentence: string, term: string): number
```

## 14. Definition quality rules

Definition suggestions should be clear and practical.

Prefer:

- short, clear definitions
- natural learner-friendly meanings
- local phrase dictionary definitions for phrases

Avoid:

- one-word definitions
- overly technical definitions unless no better option exists
- duplicate definitions

Important helper:

```ts
scoreDefinitionSuggestion(...)
```

## 15. Dictionary cache behavior

Dictionary and example lookups are cached in the database.

Model:

```txt
DictionaryCache
```

Definitions and examples should be cached separately.

Important:

Cache has versioning. If lookup quality rules change, bump cache version or include strategy/version in cache key.

Reason:

Old bad results like weak "winning formula" examples must not keep appearing forever.

Expected behavior:

- check cache first
- ignore old cache version
- fetch fresh result if cache is old
- store normalized result
- return clean response
